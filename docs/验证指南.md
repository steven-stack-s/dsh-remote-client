# 图形环境验证指南（Windows · 阶段 1）

本指南用于在 **Windows** 上验证 dsh-remote-client 阶段 1。

本开发环境是无 GUI 的 Linux 容器，因此以下内容**从未被运行验证过**：窗口能否打开、能否连通真实 dsh、托盘外观、登录态持久化、离线重连的实际行为。这份指南就是为把这些验证出来而写的。

> 📌 **Windows 特别提示**：阶段 1 的实现原本是按 macOS/Linux 习惯写的，识别出你的环境是 Windows 后，已追加修复两个会立刻暴露的阻塞项（托盘空图标可能导致托盘不出现、关窗即退出与所选能力冲突）。**请确认拿到的是包含这些修复的版本。**

## 0. 准备

### 0.0 最快路径：直接用安装包（推荐）

**如果你只想验证"客户端能不能用"，不需要装任何开发环境** —— 安装包已构建完成：

```
release/DSH Remote Client-0.1.0-setup.exe   （约 106MB，自带 Electron 运行时）
sha256: 4c63eb16ce9dd780079246d034507e0ea990634cb1475a967b196a46760c3a81
```

双击安装（不需要管理员权限），然后直接跳到 §1。

> ⚠️ 未做代码签名，SmartScreen 会提示「未知发布者」→ 点「更多信息」→「仍要运行」。

**只有需要改代码 / 重新构建时**，才需要下面的开发环境。

### 0.1 开发环境要求（仅改代码时需要）

- **Node.js ≥ 20**（[nodejs.org](https://nodejs.org/) 下载 LTS 版，安装时勾选 "Add to PATH"）
- **pnpm**：安装 Node 后开 PowerShell 执行
  ```powershell
  corepack enable
  corepack prepare pnpm@latest --activate
  ```
  （Node 自带 corepack，比 `npm i -g pnpm` 更干净）

验证：
```powershell
node -v      # 应 ≥ v20
pnpm -v
```

### 0.2 把代码拷到 Windows

仓库体积仅 **61K**（不含 `node_modules`），传输很轻。在开发机上打包：

```bash
# 开发机（Linux 容器内）
tar czf /tmp/dsh-remote-client.tar.gz \
  --exclude=node_modules --exclude=.git --exclude=out --exclude=.tmp \
  -C /workspace/code dsh-remote-client
```

Windows 10 1803+ **自带 `tar`**，可直接解压：

```powershell
# Windows PowerShell（在你想放项目的目录，例如 D:\dev）
tar xzf dsh-remote-client.tar.gz
cd dsh-remote-client
```

> 若 `tar` 不可用，改打包成 zip 再在资源管理器里解压。
> 该仓库目前**没有配置 git remote**，所以只能拷贝；若你想改用 git 协作，给它加个远程仓库即可。

### 0.3 安装依赖

```powershell
pnpm install
```

**这一步会下载约 100MB 的 Electron 二进制**（开发环境当时用 `ELECTRON_SKIP_BINARY_DOWNLOAD=1` 跳过了，Windows 上需要真实下载）。国内网络慢的话可以设镜像：

```powershell
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
```

## 1. 关键起点：优先用 `127.0.0.1` 验证，可零配置

**如果 dsh-docker 就跑在这台 Windows 上**（Docker Desktop / WSL2），用 `http://127.0.0.1:3080` 添加主机——这是最省事的路径，能一次绕开两个坑：

| 坑 | 用 127.0.0.1 时 |
|---|---|
| dsh 的 trust fence 拒绝非 loopback Host（页面能开但 `/api` 全 403） | `127.0.0.1` 是 loopback，**直接放行** —— 不用配 `DSH_TRUSTED_HOSTS`，不用装 `dsh-remote` |
| 明文 HTTP 非安全上下文（剪贴板失效） | `127.0.0.1` 是浏览器认定的可信源，**是安全上下文**，剪贴板正常 |

只有当你需要用**局域网 IP 或域名**访问时，才需要处理这两件事（见 §5）。

> Docker Desktop 默认会把容器端口映射到 Windows 的 `localhost`，所以这条路径开箱即用。

## 2. 起步：最小闭环（最高优先级）

```powershell
pnpm dev
```

**预期**：出现一个标题为「添加 dsh 主机」的窗口（560×420），含地址、显示名两个输入框和「添加并打开」按钮。

**这一步验证的是阶段 1 修的两个 P0**：
- `out/renderer/` 此前根本不生成 → **首启白屏**
- preload 此前内联了整个 npm `electron` 包 → `window.shell` 为 `undefined` → **按钮点了没反应**

**若白屏**：在窗口里按 `Ctrl+Shift+I` 开 DevTools 看 Console。`pnpm dev` 的终端也会打印主进程错误。

**若按钮无反应**：DevTools Console 里敲 `window.shell`，是 `undefined` 就是 preload 加载失败。

## 3. 核心验证：连上一台真实 dsh

在欢迎页填入地址并提交。

**预期（按顺序）**：
1. 提交后立即打开主机窗口，标题先是主机显示名；
2. **远端在线** → 出现 dsh 界面或登录页（取决于是否装了 `dsh-remote`）；
3. **远端不可达** → 壳自有的离线页，给出失败原因 + `DSH_TRUSTED_HOSTS` 提示。

**然后逐项确认**：

| 项 | 操作 | 预期 |
|---|---|---|
| 登录态持久化 | 登录 → **从托盘菜单选「退出」**（不是关窗）→ 重新 `pnpm dev` | 直接进入已登录状态 |
| 多主机隔离 | 添加第二台（可用不存在的地址）→ 切回第一台 | 两台登录态互不影响 |
| 托盘 | 看任务栏右下角（可能需要点「显示隐藏的图标」的 `^`） | 有蓝色圆点图标；右键菜单列出主机，当前主机带 `●`；含「添加主机…」「退出」 |
| 主机切换 | 托盘菜单点另一台 | 窗口切到该主机，`●` 跟着变 |
| 重置登录态 | 对某台点「重置登录态」→ 重开该主机 | 回到登录页 |
| 删除 | 删一台 | 菜单不再列出；**删光全部后仍有「添加主机…」** |
| 拖拽上传 | 拖一个本地文件进 dsh 窗口 | 作为附件进远端工作区（前端自带能力，壳未处理） |

### 3.1 Windows 特有：关窗行为（修复项，重点验证）

**修复前**：Windows 上关掉主机窗口 = 应用直接退出，托盘消失。
**修复后**：关窗应**最小化到托盘**，应用继续驻留。

**验证步骤与预期**：

| 操作 | 预期 |
|---|---|
| 点主机窗口右上角的 ✕ | 窗口消失，但**托盘图标仍在**，应用没退出 |
| 托盘菜单 → 「（主机名）」→「打开」 | 窗口重新出现并获得焦点（不是新开一个窗口） |
| 托盘菜单 → 「退出」 | **应用真正退出**，托盘图标消失 |
| 关掉「添加 dsh 主机」欢迎窗口的 ✕ | 该窗口正常关闭（**不**缩到托盘） |

> 若关窗后应用直接没了，说明 W-2 修复未生效，请回报。

## 4. 离线与自动重连（修复项，重点验证）

规格要求指数退避重试（1s→2s→4s→8s→…→30s），**此前完全没实现**。

**步骤**：
1. 打开一台已连上的主机；
2. 停掉 dsh-docker：`docker compose stop`（或 `docker stop dsh`）；
3. 观察窗口。

**预期**：
- 窗口切到离线页；
- **窗口标题出现倒计时**（形如「离线，N 秒后重试」，间隔逐次翻倍至 30s 封顶）；
- 托盘 tooltip 显示「（离线，正在重试）」，菜单项标注「（离线）」；
- 菜单里有「立即重试」，点它立刻重试。

**恢复**：`docker compose start`。

**预期**：客户端**自动恢复**到 dsh 界面，无需手动干预。

> ⚠️ 注意：如果 dsh 页面**已经在窗口里渲染过**，容器停了但前端可能仍显示旧界面（WebSocket 断开），而壳的离线页只在页面**加载失败**时触发。**若你看到"界面还在但连不上"而不是离线页，这属于预期行为** —— 请把这个现象告诉我，它决定阶段 2 要不要补「WebSocket 断开也提示离线」。

## 5. 局域网 / 远程访问（可选，进阶）

要用**局域网 IP 或域名**（不是 127.0.0.1）时：

**5.1 trust fence**（否则页面能开但 `/api` 全 403）—— 在 dsh-docker 的 `.env` 里配：
```
DSH_TRUSTED_HOSTS=192.168.1.5:3080
```
或装认证插件：
```bash
docker exec dsh dsh plugin --profile web add @xgone/dsh-remote
docker restart dsh
```

**5.2 安全上下文**（否则剪贴板失效）

壳会对**已配置的 `http://` origin** 设置 `unsafely-treat-insecure-origin-as-secure`，但**该开关只能在启动时生效**。

首次添加 `http://192.168.x.x:3080` 后，欢迎页会显示黄色提示并给**「立即重启」按钮** —— 按下它，该 origin 才会被纳入开关列表。

> 已知 UX 小瑕疵：同一会话内**重复添加同一台 http 主机**仍会再提示一次（语义上正确——它确实仍未生效，但显得啰嗦）。

**5.3 验证隔离性**：同时添加一个 `http://` 和一个 `https://` 主机，确认登录态互不干扰。

## 6. 已知限制（避免误判为缺陷）

以下是**设计上已知**的，不是 bug：

- **没有原生通知**（审批请求/任务完成不弹系统通知），属于阶段 2。
- **不能重命名主机**，属于阶段 2（添加时可填显示名）。
- **`http://` 主机换 IP 或换域名 = 新主机**，需重新登录。这是 dsh 的 cookie 名绑定 authority（`sha256(authority)`）导致的。
- **只保留一个主机窗口**：切换主机会关掉旧窗口。
- **未签名应用**：若你日后打包成 exe，Windows Defender / SmartScreen 可能警告；直接用 `pnpm dev` 开发模式跑不涉及。

## 8. 自动化部分先跑一遍（可与 GUI 验证并行）

GUI 验证前先确认自动化部分是绿的：

```powershell
pnpm test        # 构建 + 全部测试（含构建产物断言）
pnpm typecheck
```

预期：`Tests passed`、typecheck 退出码 0、`out\` 下有恰好 5 个产物文件。

这条命令在阶段 1 抓出了两个 P0（`out/renderer/` 不生成、preload 内联 electron 包），**它们单测和类型检查都抓不到** —— 所以若发现构建相关异常，`pnpm test` 是第一道筛子。
