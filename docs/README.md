# 文档索引 (docs/)

本目录只放**随代码一起演进**的文档。入口文档在仓库根目录：[`README.md`](../README.md)（英文）/ [`README.zh-CN.md`](../README.zh-CN.md)（中文）。

## 本目录内容

| 文件 | 语言 | 用途 | 什么时候看 |
|---|---|---|---|
| [`verification-guide.zh-CN.md`](verification-guide.zh-CN.md) | 中文 | **验收手册**：在一台真实 Windows 机器上逐步验证客户端的行为是否与设计一致 | 发版前、改完窗口/通知/更新相关代码后、排查「是缺陷还是设计如此」 |
| [`verification-guide.md`](verification-guide.md) | English | 同上，英文版 | 同上（英文读者） |
| [`dom-recon-script.js`](dom-recon-script.js) | 注释中文 | **DOM 特征勘察脚本**：粘进 DevTools Console，找出 dsh 前端里稳定的 DOM 信号（审批出现 / 回复结束） | 仅当 dsh 上游改版导致原生通知的选择器失效时 |

根目录另有 [`CHANGELOG.md`](../CHANGELOG.md)：按版本记录用户可感知的变化与根因，**查「某行为是什么时候变成现在这样的」先看它**。

## 文档分工

三者的边界是刻意划开的，写新文档时请先对照这张表：

| 想写的东西 | 放哪 |
|---|---|
| 用户/部署者要读的：功能、安装、前置条件 | `README.md` + `README.zh-CN.md` |
| 「这个版本改了什么、为什么」 | `CHANGELOG.md` |
| 「怎么手工验、验什么、什么现象算缺陷」 | `docs/verification-guide*.md` |
| 设计论证、实施计划、运维手册 | **不入库**，见下 |

## 为什么不入库的设计文档

设计与实施记录（差分更新的设计规格与实施计划、GitHub 下载加速通道运维手册等）**刻意保留在仓库外**，不随代码公开。这是既有约定（历史上做过一次移出，见 CHANGELOG 中 0.1.4 一节），不是遗漏。

同样地，`docs/superpowers/` 被 [`.gitignore`](../.gitignore) 排除，属于本地工作记录。

## 维护约定

写文档时请遵守已有的几条约定，它们都是踩过坑之后定下来的：

- **中英双语**：README 与验收指南各有中英两份，改一份要同步另一份。历史上多次出现只改中文、英文滞后（或反之）的情况。
- **不写死版本号**：用 `<版本>` 占位符。写死具体版本号与写死 SHA256 是同一个毛病——每次发版都会过期，而**确实漏改过**（0.1.1 发布时文档里还留着 0.1.0 的哈希）。被 URL 引用的二进制/产物名则必须写全，那不是展示用的版本号。
- **产物名以点号分隔**：`DSH.Remote.Client-<版本>-setup.exe`（从 0.1.8 起固定）。0.1.7 及更早用的是空格，而同一个空格会被 electron-builder、`latest.yml`、GitHub 三方用三种规则改写，曾导致自动更新必然 404——详见 CHANGELOG 的 0.1.7 一节。
- **区分「设计如此」与「缺陷」**：验收指南的「已知限制」一节就是为了避免把有意的取舍当成 bug 报。
- **命令与输出可复制**：给命令时连同预期输出一起给，否则读者无法判断是否通过。
